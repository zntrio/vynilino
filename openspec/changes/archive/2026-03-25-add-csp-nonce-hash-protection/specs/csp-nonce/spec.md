## ADDED Requirements

### Requirement: Per-request CSP nonce generation
The server SHALL generate a cryptographically random nonce of at least 128 bits of entropy for every HTTP request that may return an HTML response. The nonce SHALL be encoded as base64url without padding (22 characters minimum).

#### Scenario: Nonce generated per request
- **WHEN** the server processes any HTTP request
- **THEN** the security headers middleware SHALL generate a unique nonce using `crypto/rand` and store it in the request context

#### Scenario: Nonces differ across requests
- **WHEN** two separate HTTP requests are made
- **THEN** each response SHALL carry a different nonce value in its `Content-Security-Policy` header

### Requirement: CSP header uses nonce directives
The server SHALL emit a `Content-Security-Policy` header that references the per-request nonce instead of `'unsafe-inline'` or `'unsafe-eval'`. The directives SHALL be:

- `script-src 'self' 'nonce-<value>'`
- `style-src 'self' 'nonce-<value>'`

Neither `'unsafe-inline'` nor `'unsafe-eval'` SHALL appear in production CSP headers.

#### Scenario: CSP header contains nonce
- **WHEN** the server returns any HTTP response
- **THEN** the `Content-Security-Policy` response header SHALL contain `'nonce-<value>'` in both `script-src` and `style-src` directives

#### Scenario: CSP header does not contain unsafe directives
- **WHEN** the server is running in production mode
- **THEN** the `Content-Security-Policy` header SHALL NOT contain `'unsafe-inline'` or `'unsafe-eval'`

### Requirement: Nonce context propagation
The nonce generated by `securityHeadersMiddleware` SHALL be available to downstream handlers via the request context using `ctxutil.CSPNonceFromContext`.

#### Scenario: Nonce accessible in downstream handler
- **WHEN** a handler calls `ctxutil.CSPNonceFromContext(r.Context())`
- **THEN** it SHALL receive the same nonce value that was set in the `Content-Security-Policy` header for that request

### Requirement: Nonce injected into HTML entry points
The server SHALL inject the per-request nonce as the `nonce` attribute on every `<script>` and `<style>` tag in the `index.html` and `login.html` HTML entry points before sending the response.

#### Scenario: Script tags carry nonce in index.html response
- **WHEN** a browser requests `GET /` and the server serves `index.html`
- **THEN** every `<script>` tag in the response body SHALL have a `nonce` attribute matching the nonce in the `Content-Security-Policy` header

#### Scenario: Script tags carry nonce in login.html response
- **WHEN** a browser requests `GET /login` and the server serves `login.html`
- **THEN** every `<script>` tag in the response body SHALL have a `nonce` attribute matching the nonce in the `Content-Security-Policy` header

#### Scenario: Browser executes nonce-bearing scripts without CSP violation
- **WHEN** the browser loads `index.html` with a valid nonce in script tags
- **THEN** no CSP violations SHALL be reported in the browser console for any script or style resource belonging to the application

### Requirement: HTML entry points not cached
Responses serving `index.html` or `login.html` SHALL include `Cache-Control: no-store` to prevent intermediate proxies or browsers from caching an HTML response with a stale nonce.

#### Scenario: index.html response not cached
- **WHEN** the server serves `index.html`
- **THEN** the response SHALL include `Cache-Control: no-store`

#### Scenario: login.html response not cached
- **WHEN** the server serves `login.html`
- **THEN** the response SHALL include `Cache-Control: no-store`

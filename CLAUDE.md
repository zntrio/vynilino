# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```bash
# Build (includes UI build)
make build

# Run tests
go test ./...

# Run a single test
go test ./internal/app/... -run TestMyFunction

# Lint
make lint          # go vet + golangci-lint

# Regenerate GraphQL code (after schema changes)
go run github.com/99designs/gqlgen generate

# Regenerate SQL queries (after query/migration changes)
sqlc generate

# Run server locally
VYNILINO_ENV=development VYNILINO_TOKEN_KEY=$(openssl rand -hex 32) go run ./cmd/vynilino serve

# UI development (requires running Go backend separately)
make ui-install    # first time
make ui-dev        # Vite dev server at http://localhost:5173
make ui-build      # build assets into web/dist/
```

## Architecture

Vynilino is a self-hosted vinyl record manager: a single Go binary embedding both a GraphQL API and a lightweight Alpine.js/Tailwind UI. All data lives in SQLite.

### Dependency injection

The `serve` command wires the entire application using **uber/fx**. All providers are registered in `cmd/vynilino/internal/cmd/serve.go`. When adding a new service or adapter, register it there.

### Layer structure

```
cmd/vynilino/           → Cobra CLI (serve + user subcommands)
internal/
  domain/               → Pure types and repository interfaces (User, Record, Token, OIDCIdentity)
  app/                  → Application services: UserService, RecordService, DiscogsService, OIDCService
                          Also: EventBus (in-process pub/sub for GraphQL subscriptions, scoped per userID)
  adapter/
    graphql/            → Chi router + gqlgen GraphQL server, middleware, REST handlers
    graphql/graph/      → Generated gqlgen code + resolvers (schema.resolvers.go)
    storage/sqlite/     → Repository implementations; sqlcdb/ is sqlc-generated, do not edit manually
    discogs/            → Discogs API client (wraps go-discogs)
    filestore/          → Cover-art local filesystem store
    ui/                 → SPA handler (serves web/dist/), /api/me, /api/upload
  config/               → Config loaded from environment variables
  ctxutil/              → Request-scoped context helpers (UserID, etc.)
web/                    → go:embed target for compiled UI assets (web/dist/)
ui/                     → Vite + Alpine.js frontend source
openspec/               → OpenSpec specs and archived change history (decision log)
```

### Key patterns

- **Domain interfaces** are defined in `internal/domain/`; adapters implement them. Services depend only on interfaces, not concrete types.
- **GraphQL resolvers** (`internal/adapter/graphql/graph/schema.resolvers.go`) call application services. `generated.go` and `models_gen.go` are generated — do not edit.
- **SQLite queries** in `internal/adapter/storage/sqlite/sqlcdb/` are generated by sqlc from SQL files in `queries/` and `migrations/`. Edit the SQL files, then run `sqlc generate`.
- **Authentication** uses PASETO tokens (`zntr.io/paseto`). The `AuthMiddleware` in `graphql/middleware.go` populates the user ID in the request context; `ctxutil.UserIDFromContext` retrieves it.
- **OIDC** is optional: enabled only when `VYNILINO_OIDC_ISSUER` is set.
- **EventBus** (`app/eventbus.go`) routes `RecordChangedEvent` to GraphQL subscription channels, keyed by userID.
- **Static assets** are embedded via `//go:embed all:dist` in `web/embed.go`. The build order is: `ui build` → `go build`.

### Code generation files (do not edit manually)

- `internal/adapter/graphql/graph/generated.go`
- `internal/adapter/graphql/graph/models_gen.go`
- `internal/adapter/storage/sqlite/sqlcdb/*.go`

### OpenSpec workflow

Non-trivial changes follow the OpenSpec spec-driven workflow. Proposals and designs live in `openspec/changes/`; completed changes are archived in `openspec/changes/archive/`. Use `/openspec-propose` to start a new change.
